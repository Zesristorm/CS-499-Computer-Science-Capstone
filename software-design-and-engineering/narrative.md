# Software Design and Engineering Narrative

For the enhancement, I selected my event-tracking app from CS 360: Mobile Architecture and Programming. I originally created this app to help users organize their schedules by creating an account, logging in, adding events, viewing events in a weekly or full calendar view, editing event details, marking events as complete, and deleting events. The app was built in Android Studio using Java and SQLite. I chose this artifact because it shows several skills I developed during the Computer Science program such as mobile application development, user interface design, data storage, and problem solving. However, the original version placed too much responsibility inside the Activity classes. The screens handled user actions, validation, and database calls all in the same files which made the code harder to maintain and expand. For the enhancements, I reorganized the application using the MVVM and Repository patterns.

As I worked on the app, I focused on improving how the code was organized behind the scenes. In the original version, the Activities handles almost everything including button clicks, validation, navigation, and database calls. I separated those jobs by adding EventViewModel and LoginViewModel for screen logic and EventRepository and UserRepository for database access. For example, when a user saves an event, AddEventActivity now passes the information to EventViewModel instead of writing directly to SQLite. I also used LiveData to send results back to the screen and an ExecutorService to keep database work from slowing down the user interface. Through these changes, I practiced MVVM architecture, the repository pattern, separation of concerns, lifecycle aware development, background processing, and debugging. This connects to program outcome 4 because I used standard android development tools and practices to make the app easier to maintain, expand, and troubleshoot. It also connects to outcome 2 because I made the code easier to follow through clearer class names, smaller methods, reusable strings, and comments.

The hardest part of the enhancement was changing the structure without breaking features that already worked. A small mistake such as using the wrong Intent key for eventId or naming a method differently in two files could stop the edit screen from loading the saved event information. I also learned that a successful build does not always mean the app works correctly, so I tested each feature din the emulator after making changes. This included logging in, creating accounts, adding and editing events, marking events complete, switching between the week and calendar views, and checking that each user only saw their own events. Working through these issues helped me understand why professional developers make changes in smaller steps and test often instead of rewriting the entire application at once. 

I believe this enhancement met the main outcome, outcome #4, I planned for. The app now uses a cleaner structure, separates the screen code from the data code, and handles database work in a way that is easier to maintain. I also made progress towards outcome #2 by improving the organization of the project and making the code easier for another person to read. I made some progress towards outcome #5 as well by keeping user event data separated and checking the username during event updates and deletions. However, I did not complete the larger security changes. Password hashing, email recovery, and database changes will be completed during the database enhancement so the two categories stay separated.
