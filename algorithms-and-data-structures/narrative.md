# Algorithms and Data Structures Narrative

For this enhancement, I selected my text adventure game from IT-140: Introduction to Scripting. The game is a dramatic fantasy story where the player takes the role of a Duke’s daughter who has been labeled as the villainess. Her goal is to explore an imperial castle, collect useful items, defeat the Saintess, marry the Emperor, and become Empress.

I chose this artifact because it was one of my first complete programming projects. It helped me understand how different parts of a program work together. It was also one of the most enjoyable projects I completed during my degree program. The original game worked, but it was stored in one file, the items were mostly there to meet the project requirements, and the battle system had limited choices. The original version also did not handle invalid input very well.

One of the first changes I made was separating the game into different files. The main game, castle map, items, room challenges, and battle system are now handled separately. This made the project easier to work with because I did not have to search through one long file every time I wanted to make a change. It also helped me better understand how different parts of a program can work together without everything being placed in one location.

I kept the castle rooms inside a nested dictionary. Each room contains the directions the player can travel and the rooms connected to those directions. This works like a graph, with each room acting as a location and each direction acting as a path. I also changed the inventory from a list to a set. The set keeps the player from collecting the same item more than once and makes it easier to check whether an important item has already been collected. For example, the game checks for the Crown Sigil before allowing the player to enter the throne room.

I also wanted the journey through the castle to feel more important. In the original game, the player could simply enter a room and collect an item. In the enhanced version, each equipment room has a riddle that must be answered before the reward is given. The player can collect the Poisoned Dagger, Royal Gown, Enchanted Amulet, Crown Sigil, and Grimoire of Restoration. The player can also choose one potion in the Alchemy Atelier. Each item has a purpose in the final battle instead of only sitting in the inventory.

The battle system was the biggest part of the enhancement. The player can use a normal dagger attack, a stronger poison attack, dodge, activate the amulet, use a potion, or heal with the grimoire. The Royal Gown protects the player until its health reaches zero. After it breaks, attacks begin lowering the player’s health. Poison lasts for two turns, while cooldowns stop stronger actions from being used over and over. The Saintess can attack, heal, purify poison, create a barrier, and change her behavior as her health gets lower.

The hardest part was making the battle feel fair. During the first few tests, attacking over and over was usually the best strategy. Dodging and healing could make the fight last longer, but they did not always help the player win. That made me realize that adding more choices does not matter if some of them are not worth using. I changed successful dodges so they also cause a small counterattack. I also changed the amulet and potions so the player could use them without losing the entire turn.

I tested the battle several times using different choices. I tried aggressive attacks, frequent dodging, healing, poison attacks, and different potion options. I adjusted the Saintess’s health, healing, barrier strength, dodge chance, and counterattack damage based on those tests. I also used outside QA feedback during testing. Alex Sherrell, a manager at Riot Games, provided feedback through Discord that helped me look at the game from a player and quality assurance perspective. This feedback helped me focus on clearer commands, smoother gameplay, and better testing before final submission (A. Sherrell, personal communication, July 25, 2026).

This project mainly connects to program outcome #3. I used dictionaries, sets, classes, loops, functions, and decision-making logic to improve the game. I also had to think about the trade-offs between difficulty, fairness, efficiency, and player choice. Dictionary and set checks are generally O(1), so the program can quickly look up rooms, items, and completed challenges without searching through long lists.

This project also connects to program outcome #4 because I improved the structure of the program and used better Python practices. The updated game is easier to read, maintain, and expand because the code is separated into clear sections. I also added reusable input checks so the program does not crash when the player enters a word, blank response, or number outside of the available choices.

Overall, this enhancement shows growth in algorithms and data structures because the game became more than a simple room-based project. It now has organized files, better data structures, improved command handling, item-based progress, battle logic, testing, and feedback-based changes. These improvements helped make the game clearer, more balanced, and easier to maintain.
